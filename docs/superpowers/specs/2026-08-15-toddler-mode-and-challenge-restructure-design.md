# 유아용 모드 신설 + 챌린지 모드 재구성 설계

## 배경/목표

기존 구조: Child 모드(=지금 "유아용"이라 부르는 것) 100개 도안(레벨1~10 × 10개, 영역개수 오름차순 난이도) + 챌린지 모드 4단계(쉬움/보통/어려움/매우어려움, 각 100개, 티어별 레벨1~10 × 10개). 쉬움 티어는 Child 모드 100개를 재사용.

문제 제기(대화 중 사용자 피드백):
- 유아용에 어울리지 않게 영역이 복잡한 도안이 섞여 있음 → **영역개수 기준으로 유아/챌린지를 다시 나누고 싶음**
- 챌린지를 카테고리(주제)별로 묶고 싶은데, 그러면 난이도 배치가 애매해짐 → 해결 방법 논의
- 시계(clock2~12) 같이 서로 거의 똑같이 생긴 도안이 한 레벨에 몰리는 문제 → **레벨 하나 안에서는 카테고리가 최대한 안 겹치게**

## 확정된 결정 사항

1. **유아용 모드가 기존 Child 모드를 완전히 교체**한다(별도 모드 신설 아님).
2. 전체 400개 도안(Child 100 + 챌린지 전용 300)을 하나의 풀로 놓고, **카테고리 10개 x 10개 = 100개**를 유아용으로 뽑는다. 카테고리별로 **영역개수가 가장 적은 10개**를 유아용으로 보낸다(카테고리마다 전체 개수가 10개 이상이라 부족 없이 다 채워짐 — 실측 확인됨).
3. 유아용은 **난이도 순서 없음** — "레벨" 10개 = 카테고리 10개, 각 레벨(카테고리) 안 10개는 순서 무관.
4. 나머지 300개가 챌린지 모드 전체 풀이 된다(유아용에 쓴 100개와 절대 안 겹침, 뺄셈으로 자동 보장).
5. 챌린지 모드는 **쉬움/보통/어려움 3단계**로 축소(기존 4단계에서 매우어려움 제거 — 유아용이 예전 "가장 쉬운 100개" 역할을 흡수했으므로). 300개를 **영역개수 오름차순으로 100개씩 3등분**.
6. 각 티어(100개) 안에서 **레벨1~10 × 10개**로 배치. 레벨 간에는 영역개수가 오름차순으로 커져야 함. 레벨 하나(10개) 안에서는 **카테고리가 최대한 안 겹치게** 배치(완전히 겹침 없음은 불가능 — 아래 트레이드오프 참고). **사용자가 이 결과를 그대로 승인함.**

## 카테고리 정의 (10개, 병합됨)

기존 20개 세부 분류를 병합:

| 병합 카테고리 | 구성 | 전체(400) 개수 |
|---|---|---|
| 동물 | 동물 | 39 |
| 자연 | 바다생물+곤충+식물 | 39 |
| 음식 | 음식+과일채소 | 53 |
| 하늘 | 하늘/우주/날씨 | 25 |
| 탈것/장소 | 탈것+장소 | 42 |
| 사람 | 표정/제스처+패션 | 37 |
| 생활용품 | 집+사무+전자+안전 | 75 |
| 놀이 | 스포츠+파티 | 36 |
| 시계 | 시계/시간 | 15 |
| 기호/기타 | 기호+기타 | 39 |

세부 id→카테고리 매핑은 대화 중 스크립트(`scripts/_tmp-*.js`, 실행 후 삭제됨)에 있던 400개 전체 수작업 분류 결과를 그대로 쓴다 — **이 스펙을 구현할 때 다시 만들어야 하므로, 최종 카테고리 매핑 표를 이 문서에 첨부하거나 구현 시점에 별도 데이터 파일로 고정해야 함**(TODO: 구현 계획 단계에서 정리).

## 트레이드오프: 레벨 내 카테고리 중복

300개를 영역개수로 순수 3등분하면 카테고리가 특정 난이도대에 쏠린다(예: 쉬움 티어에 생활용품 25개, 사람 16개 — 레벨 10개에 다 못 나눠 담음). 실측 결과 최선의 배치(카테고리별 순위를 레벨에 고르게 분산 + 넘치는 레벨→모자란 레벨 재배치)로도 **레벨 30개 중 다수에서 카테고리 1~2종류가 2개씩 들어감**은 불가피. 사용자가 이 결과를 확인하고 그대로 진행하기로 확정함(추가 조정 없음).

## 영향받는 코드 (구현 계획 단계에서 상세화)

- `templates.js`: `COLORING_TEMPLATES`(유아용 100개로 전면 교체), `CHALLENGE_TIER_TEMPLATES`(300개, challengeTier를 easy/normal/hard 3종으로, challengeLevel 1~10 재배치), `TEMPLATE_REGION_COUNTS`/`CHALLENGE_TIER_REGION_COUNTS`(도안 자체는 안 바뀌므로 기존 실측값 재사용 가능, id 재분류만 반영)
- `app.js`: Child 모드의 레벨 선택/진행 로직 — "레벨=난이도"였던 걸 "레벨=카테고리"로 바꿔야 함(난이도 정렬 로직 제거, 카테고리 라벨 표시 추가 등)
- `challenge.js` / `challenge-config.js`: 티어 4개→3개(버튼 UI, `DIFFICULTY_TIME`/`DIFFICULTY_SCORE_MULTIPLIER`의 `easy` 키 처리 방식 결정 필요 — 쉬움 재정의됐으므로 값 재검토 필요할 수 있음), `getChallengeTierTemplates` 자체 로직은 안 바뀌어도 됨(필터+정렬 방식 동일)
- `index.html`: 챌린지 난이도 선택 버튼 4개→3개
- 레벨별 연출(LEVEL_EFFECTS 1~10: 스파이럴/날씨/회전 등, 이번 세션에서 만든 것들)은 **문제 번호(1~10) 기준으로 동작하므로 이번 재구성과 무관, 그대로 유지**

## 확인 안 된 것 (구현 전 재확인 필요)

- **기존 플레이어 진행 데이터(로컬 저장 점수/랭킹) 초기화 여부** — 사용자에게 질문했으나 아직 명시적 답 없음. 배포된 사이트에 실제 플레이 기록이 있다면 마이그레이션 필요, 없다면 그냥 리셋으로 처리. **구현 착수 전 반드시 확인.**
